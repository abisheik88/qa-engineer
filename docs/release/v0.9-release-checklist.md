## The product, end to end, on real data

Not fixtures — the repository's own runnable example, executed with a real
browser, then pushed through the deterministic pipeline.

```console
$ cd examples/getting-started && npx playwright test --reporter=json
expected: 2   unexpected: 0   flaky: 0

# a genuine failure, seeded by breaking one assertion
$ npx playwright test --reporter=json > failed.json     # runner exit 1
$ python3 -m playwright_analysis report failed.json      # tests: 1 failed, 1 passed
$ python3 -m qa_diagnostics.cli report --execution-result normalized.json
  classification: timeout        confidence: 0.75
  owner: test-author-or-environment   priority: P2
  repair candidate: wait-strategy     risk: medium
  release readiness: ready-with-risks
```

On a **passing** run the same pipeline produced zero findings — the engine invents
nothing when there is nothing to report.

## Packaging

The published artifact is the product, so it was inspected after extraction
rather than inferred from `files[]`.

- **Present:** CLI entrypoint and its manifest, `qa_analysis`, `qa_diagnostics`,
  both CLIs, all four framework analyzers, the framework registry, 19 schemas
  (12 skill contracts + context + internal seams + installer config), all 13
  skills, README, COMPATIBILITY, LICENSE.
- **Absent, deliberately:** `__pycache__`/`*.pyc` (0), test files (0), `docs/` (0),
  `examples/` (0).
- **Version resolution:** `0.9.0` from the tarball, and written correctly into the
  consumer's lockfile.
- A release gate fails the build if the tarball omits anything the installer
  bundles — the class of defect that made the published CLI report `0.0.0`.

## Security

| Check | Result |
| --- | --- |
| Path traversal via a hostile `qa-lock.json` | ✅ refused, exit 1, nothing removed |
| Transaction containment (write and delete) | ✅ absolute, `..`, and empty paths rejected |
| Lockfile schema rejects escaping paths on read | ✅ verify/repair/uninstall fail closed |
| Overwrite protection for un-owned files | ✅ exit 3; `--force` backs up first |
| Rollback on failure | ✅ transactional, backup-then-mutate |
| Code execution at install time | ✅ none — hostile `preinstall`/`prepare` never ran |
| Shell injection surface | ✅ no `shell: true`, no `eval`, 4 argv-array `spawnSync` sites |
| Credential redaction | ✅ bearer token in a HAR: 0 leaked occurrences |
| Artifacts and repository files treated as untrusted data | ✅ stated in skill guardrails |

One blocker was found during the audit — `uninstall` could be redirected outside
the project by a `..` path in a committed lockfile — and was fixed with layered
defence plus six regression tests. The original exploit was re-run against the fix
and is closed.

## Known limitations

Disclosed, not worked around. None blocks a preview; the first two block 1.0.

1. **No real agent has been measured.** Both eval layers score committed JSON: the
   deterministic gate scores hand-authored case outputs, and the CI "live" layer
   replays hand-authored captures against an all-`1.0` baseline. This is a working
   scorer and harness with **zero** real samples. Closing it needs hosted-agent API
   access and `run_live.py --provider command`. Until then the pack claims
   *deterministically verified*, never *behaviorally benchmarked*.
2. **Not published; identity unconfirmed.** `npx qa-automation-pack` resolves
   correctly given the package exists under that name — verified via a locally
   installed tarball. The name is not claimed and nothing is on npm.
3. **Three frameworks are gated.** Selenium, Cypress, and WebdriverIO detect and
   normalize but do not execute or generate. Labelled Beta and mechanically checked.
4. **`shared/ci/` and `shared/stacks/` are unauthored** — scope notes only, labelled
   as such wherever referenced, recorded as open M3 scope.
5. **Python 3.8 is not executed in CI** (hosted runners no longer provide it). The
   floor is enforced by parsing every module at `feature_version=(3, 8)` and
   screening for post-3.8 stdlib APIs. Real coverage, but not a test run.
6. **Agent activation accuracy is unproven** — nothing tests that the right skill
   activates among twelve competing descriptions.
7. **The runnable example is not exercised in CI** (browser download cost), so it
   can rot between manual runs. It passes today, verified above.
8. **Community files missing:** `GOVERNANCE.md`, `MAINTAINERS.md`, `SUPPORT.md`, and
   the "add a framework" / "add a skill" runbooks.

## Release engineering

Simulated end to end on a `v0.9.0` tag; nothing published.

- Version consistency: root `0.9.0` = installer `0.9.0`; semver valid.
- Tag validation: `v0.9.0` accepted, `v9.9.9` correctly rejected.
- `CHANGELOG.md` carries `## [Unreleased]` (required by release validation).
  Changelog entries are authored by hand — there is no generation tooling.
- Release workflow runs installer tests, Python suites, evals, structural and
  documentation validators, release validation, then packs.
- `npm publish` is double-gated (`if: false` plus a `TODO` requiring maintainer
  action). No tag was created by this audit.

## Go / No-Go

**✅ GO — release `v0.9.0` as a public preview.**

The mechanics a user will exercise are verified from the real published artifact,
in a clean room, including the deterministic engine running inside a consumer
project. The two things that keep this from being 1.0 — an unmeasured real-agent
accuracy number and an unpublished package identity — are stated plainly in the
repository rather than implied away, which is exactly what makes a preview
honest.

Remaining maintainer actions, deliberately not taken here:

1. Confirm and claim the GitHub org and npm package name.
2. Create the `v0.9.0` tag.
3. Flip the publish gate in `.github/workflows/release.yml`.
4. Watch the first real CI run — every gate has been executed locally, but no
   workflow has yet run on a hosted runner.
